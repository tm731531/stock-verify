## 一、信號邏輯審查

### L1: SMA黃金叉 (主信號, 60%權重)

**邏輯說明**:
```
進場: SMA20 > SMA50 (黃金叉)
出場: SMA20 < SMA50 (死亡叉)
倉位: 牛市1.0口, 空頭年0.5口
持倉: 平均140天, 最長730天限制
```

**審查項目** (打勾表示確認):

- [ ] **計算標準性**: SMA20和SMA50是否使用標準簡單移動平均公式?
  - 應為: SMA_n = AVERAGE(Close[-n:])
  - 不應為: 指數移動平均(EMA)或加權平均
  - **核查方法**: 檢查 `/backtest/adaptive_backtest_v11.py` 中的SMA計算代碼

- [ ] **窗口大小準確性**: 20日和50日窗口是否固定無變化?
  - 問題: 某些系統會動態調整窗口大小 (如考慮市場休市)
  - 驗證: 檢查2019年和2025年的計算是否一致
  - **重點**: 不能因為市場假期就改變窗口定義

- [ ] **未來數據漏洞**: 進場信號是否使用了未來數據?
  - 違規例子: SMA20在第21天才計算出來, 但卻在第20天進場
  - 正確做法: 在bar收盤后才檢查信號, 第二天才進場
  - **驗證**: 檢查進場日期是否都在SMA計算完成后的第二天

- [ ] **黃金叉定義清晰**: 進場時是否必須是「首次叉」還是「保持高於」?
  - 重要: 可能導致進場信號數量差異很大
  - 建議: 應該明確「首次SMA20>SMA50」而不是「任何SMA20>SMA50的持倉期間」
  - **驗證記錄**:
    ```
    交易#3: 2020-10-27進場 (真實黃金叉 OR 多頭持續?)
    交易#7: 2021-11-11進場 (真實黃金叉 OR 多頭持續?)
    ```

- [ ] **信號延遲可接受**: SMA有1-3天的延遲, 這是否被接受?
  - 理由: 移動平均線本質上是滯後指標
  - 影響: 進場時已經上漲了幾個百分點
  - **評估**: 14筆交易中的進場點位是否都在合理延遲範圍?

- [ ] **出場信號清晰**: 死亡叉出場是否有其他條件?
  - 檢查點: 是否因止損/止盈/超時而提前出場?
  - **驗證**: 18筆交易中是否都明確記錄出場原因?

**總體評價**:
- [ ] ✓ L1邏輯清晰, 可信度高
- [ ] ⚠️ L1邏輯有改進空間
- [ ] ✗ L1邏輯有重大缺陷

### L3: 布林帶反彈 (防守信號, 15%權重)

**邏輯說明**:
```
進場: Close < BB下軌 AND RSI < 30 (超賣)
出場: Close > BB中軌 OR RSI > 50 (超買)
倉位: 0.5口 (固定反彈單)
持倉: 平均20天, 最長25天限制
```

**審查項目**:

- [ ] **布林帶計算準確**: BB計算是否使用標準公式?
  - 標準公式:
    ```
    BB_Mid = SMA(Close, 20)
    σ = StdDev(Close, 20)
    BB_Up = BB_Mid + 2σ
    BB_Low = BB_Mid - 2σ
    ```
  - **問題**: σ計算時是否使用樣本標準差(n-1)還是總體標準差(n)?
  - **驗證**: 檢查代碼中的 `np.std()` 參數 (ddof=1 vs ddof=0)

- [ ] **RSI計算標準性**: RSI是否使用14日窗口?
  - 標準公式:
    ```
    RS = 平均漲幅 / 平均跌幅 (14日)
    RSI = 100 - 100/(1 + RS)
    ```
  - **警告**: 某些系統使用21日或其他窗口, 會影響信號

- [ ] **雙條件邏輯驗證**: 「Close < BB_Low AND RSI < 30」是否必須同時滿足?
  - **問題**: 實際回測中是否存在「只滿足其一」就進場的情況?
  - **驗證**: 檢查4筆L3交易是否都同時滿足兩個條件
    ```
    交易#1: 2019-11-05, Close=11,644, BB_Low=?, RSI=?
    交易#4: 2021-04-08, Close=16,596, BB_Low=?, RSI=?
    交易#9: 2022-09-29, Close=13,534, BB_Low=?, RSI=?
    交易#11: 2023-02-14, Close=15,654, BB_Low=?, RSI=?
    ```

- [ ] **條件是否過於寬鬆**: 超賣定義(RSI<30)是否太敏感?
  - **觀察**: 4筆交易中3筆虧損, 可能信號質量不佳
  - **建議**: 考慮加強到「同時滿足+成交量確認」

- [ ] **出場條件優先級**: 是否明確了出場優先級?
  - **問題**: Close > BB_Mid 和 RSI > 50 哪個先?
  - **影響**: 交易#9出場條件無法驗證, 可能存在隱含條件
  - **驗證**: 檢查原始數據中的RSI和BB值

- [ ] **超時平倉機制**: 25天超時是否確實執行?
  - **問題**: 部分L3交易持倉超長 (交易#11: 86天, 交易#9: 40天)
  - **評估**: 超時機制是否失效?

**總體評價**:
- [ ] ✓ L3邏輯完整
- [ ] ⚠️ L3質量需改進 (4筆中3筆虧損, 持倉過長)
- [ ] ✗ L3邏輯有重大缺陷

## 二、風險管理審查

### 倉位管理審查

**規則**:
```
牛市年: L1(1.0) + L2(0.5) + L3(0.5) = 最多1.5口
空頭年: L1(0.5) + L2(0.5) + L3(0.5) = 最多1.0口
```

**審查項目**:

- [ ] **最大倉位限制合理性**: 1.5口(牛市)是否適當?
  - **考慮因素**: 初資¥50,000 × 10倍槓桿 = ¥500,000敞口
  - 1.5口 = ¥750,000敞口 (150% 資金)
  - **問題**: 是否過於激進? 建議初期1.0口
  - **風險**: 如果每口虧損¥1,500, 則月度虧損¥2,250 (-4.5%)

- [ ] **無加倉機制是否適當**: 為何不支持追加加倉?
  - **優點**: 保守, 避免「越跌越買」
  - **缺點**: 可能無法最大化趨勢
  - **建議**: 接受此設計, 它符合風險管理原則

- [ ] **倉位是否動態調整**: 環境從牛轉熊時如何處理?
  - **問題**: 是否需要立即從1.0口降至0.5口?
  - **驗證**: 檢查2022年初的倉位調整
  - **評估**: 環境檢測的延遲是否可接受?

- [ ] **多口位持倉風險**: 同時持有多個L1和L3倉位時, 總敞口是否監控?
  - **警告**: 同時持有1.0口L1 + 0.5口L3 = 1.5口敞口
  - **風險**: 單日-3%大跌會造成-4.5%月度虧損

**總體評價**:
- [ ] ✓ 倉位管理保守合理
- [ ] ⚠️ 倉位管理可更嚴格
- [ ] ✗ 倉位管理風險過高

### 換倉成本審查

**成本估算**:
```
進出場成本: ¥600/筆 × 18筆 = ¥10,800
月度換倉: ¥6,100/月 × 12月 × 7年 = ¥524,600
合計年度成本: ~¥73,200 (年化 -0.73%)
```

**審查項目**:

- [ ] **¥6,100/月的估算是否準確?**
  - **成本構成**:
    ```
    手續費: ¥50 × 2 (進出場) = ¥100
    稅務: ¥2,000 × 0.5% = ¥10,000??? (這不對)
    基差風險: ¥1,000/月
    滑點: ¥3,000/月
    ```
  - **問題**: 稅務和滑點估算是否過高?
  - **建議**: 驗證實盤時的實際成本

- [ ] **是否考慮了成交量影響基差?**
  - **問題**: 大額平倉時基差可能擴大
  - **驗證**: 初資¥50,000 × 10倍 = 1.5口名義敞口
  - 流動性風險: 台指期日均成交量充分, 應無問題

- [ ] **是否應該季度換倉而非月度換倉?**
  - **當前**: 月度換倉(假設成本¥6,100/月)
  - **優化**: 季度換倉(成本¥18,300/季, 但滑點大)
  - **評估**: 月度更頻繁, 但成本小

- [ ] **滑點成本是否已充分計入回測?**
  - **驗證**: 檢查回測數據是否使用了：
    - 進場: 該日收盤價 (還是高價?)
    - 出場: 該日收盤價 (還是低價?)
  - **問題**: 實盤進場時應該用更高的價格進場

**總體評價**:
- [ ] ✓ 換倉成本估算合理, 已計入回測
- [ ] ⚠️ 滑點估算需驗證
- [ ] ✗ 成本估算過低

### 出場邏輯

**規則**:
```
[信號出場] SMA20 < SMA50 (L1) 或 RSI > 50 (L3)
[止損出場] 虧損 ≤ -15%
```

**審查項目**:

- [ ] **固定止盈是否過於死板**: +30%固定止盈會錯過大行情

- [ ] **出場時是否檢查新進場機會**:

  - **場景**: 同時達到信號出場和止損

**總體評價**:
- [ ] ✓ 出場邏輯完整
