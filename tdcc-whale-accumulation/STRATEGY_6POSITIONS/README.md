# TDCC 雙引擎量化策略 - 6持仓版本

**策略版本**：v1.0
**生成日期**：2026-03-07
**回测周期**：2022-11-18 ~ 2026-02-26（170 週）
**回测結果**：+94.58% 累計報酬（年化 28.9%）

---

## 📋 策略概述

本策略是基於 TDCC 大戶持股變化的量化交易系統，採用**雙引擎設計**，結合主引擎和備用引擎的信號，透過持仓管理和止損機制控制風險。

### 核心要素

| 項目 | 設定 |
|------|------|
| **初始資本** | 500,000 元 |
| **最大持仓** | 6 個 |
| **單持仓金額** | 83,333 元 |
| **持仓期限** | 4 週（28 日曆日） |
| **每周進場** | 最多 2 筆（實際平均 5.3 筆） |
| **年化報酬** | 28.9% |

## 🎯 進場邏輯

### 主引擎（信號數量：1,250 個）

**條件**：3 週連續上升 + 同步比達標 + 散戶減少

```
1. ratio_400_above 連升 3 週
   - 第 i 週：ratio_400[i] > ratio_400[i-1]
   - 第 i-1 週：ratio_400[i-1] > ratio_400[i-2]
   - 第 i-2 週：ratio_400[i-2] > ratio_400[i-3]

2. 連升幅度 ≥ 3%
   - change = ratio_400[i] - ratio_400[i-3] ≥ 3.0

3. 同步比 ≥ 50%
   - sync_ratio = (ratio_1000[i] - ratio_1000[i-3]) / (ratio_400[i] - ratio_400[i-3])
   - sync_ratio ≥ 0.5
   - （表示大戶內部多層級的一致性）

4. 散戶逃離 ≥ 2%
   - holder_change = (total_holders[i] - total_holders[i-3]) / total_holders[i-3]
   - holder_change ≤ -0.02
   - （表示散戶減少，大戶開始有機會）

5. 排除條件
   - 排除 ETF（代碼以 00 開頭）
   - 排除公開收購（ratio_400_above = 100）
   - 排除持仓人數少於 5 人的股票
```

**進場時機**：信號出現後的下一個交易日（買入）

### 備用引擎（信號數量：452 個）

**條件**：散戶大幅出逃 + 大戶趁機佈局

```
1. 3 週散戶逃離 ≥ 15%
   - holder_change = (total_holders[i] - total_holders[i-3]) / total_holders[i-3]
   - holder_change ≤ -0.15

2. 大戶持股增加 ≥ 2%
   - r400_change = ratio_400[i] - ratio_400[i-3] ≥ 2.0

3. 含義：散戶恐慌式拋售，大戶趁低佈局
```

**進場時機**：信號出現後的下一個交易日（買入）

## 📊 出場邏輯

### 1. 止損出場（-7%）

```
條件：股價跌幅達到 -7%
效果：硬性停損，防止虧損擴大

數據：460 筆交易止損出場，平均虧損 -7.44%
提示：表示約 30% 的交易是錯誤信號
```

### 2. 追蹤止盈出場（+15% 觸發，-10% 拉回）

```
第一步：當股價漲幅達到 +15% 時
  → 啟動追蹤模式，記錄最高價

第二步：股價向下拉回 -10% 時
  → 立即出場（鎖定利潤）

效果：捕捉趨勢行情，同時保護已有利潤

數據：12 筆交易追蹤止盈出場，平均獲利 +11.67%
提示：雖然筆數少（4.4%），但是最優質的交易
```

### 3. 持仓期滿出場（4 週）

```
條件：持仓滿 4 週後，不論盈虧，強制平倉

效果：限制持仓時間風險，確保資本周轉

數據：142 筆交易期滿出場，平均獲利 +9.15%
提示：最常見的出場方式（52%），獲利穩定
```

### 4. 資料截斷出場

```
條件：回測資料結束，強制平倉所有未平倉頭寸
效果：回測用，實際交易中不適用
```

### 進場優先級

```
實際進場排序（同一天有多個信號時）：

1. 主引擎信號優先於備用引擎
2. 信號在當天出現順序
3. 受持仓滿度限制
4. 受現金可用度限制

備註：每週最多 2 筆的限制在實際執行中基本不生效
      因為持仓滿了會自動排隊等待
```

### 出場優先級

```
同一天出場優先順序：

1. 觸發止損的頭寸（強制）
2. 持仓滿 4 週的頭寸（到期）
3. 追蹤止盈的頭寸（移動目標）

釋放的資金用於：
  → 新的進場信號
  → 保持充足現金儲備
```

## ⚠️ 風險提示

### 1. 胜率偏低（36.9%）

```
含義：3 次進場中，約 2 次虧損，1 次獲利
原因：信號存在假訊號（約 30%）

缓解措施：
  • 持续監控信號質量
  • 考虑添加額外過濾條件
  • 定期調整信號參數
```

### 2. 媒数報酬為負（-3.34%）

```
含義：一半以上的交易虧損或獲利很少
原因：獲利交易時間短（期滿），大小虧損齊下

缓解措施：
  • 增加追蹤止盈的觸發機會
  • 優化信號進場時機
  • 考虑縮短持仓期限到 3 週
```

### 3. 備用引擎無效（6 筆信號）

```
含義：備用引擎本應有 452 個信號，卻只執行 6 筆
原因：主引擎信號過多，占滿所有持仓

解決方案：
  • 為備用引擎保留 2 個固定持仓
  • 或提升備用引擎信號優先級
  • 或放寬持仓限制到 8 個
```

### 4. 執行率低（16.1%）

```
含義：1,702 個信號只執行 274 筆
原因：持仓滿 + 資金限制

潛在改進：
  • 增加持仓數到 8 個（預期 +3-5% 年化）
  • 放松週進場限制（實際影響小）
  • 優化信號篩選（減少低質量信號）
```

## 📝 実施指南

### 每週操作流程

```
週一/週二（掃描階段）
  1. 下載最新 TDCC 數據（上週五公佈）
  2. 計算所有股票的 ratio_400_above / ratio_1000_above
  3. 識別主引擎和備用引擎信號
  4. 統計今週的買入機會
  5. 檢查當前持仓狀態

週二/週三（執行階段）
  1. 按優先級排列信號
  2. 下單買入（最多 2 筆，或根據持仓空間調整）
  3. 設置止損單（-7%）
  4. 記錄進場信息

週四/週五（監控階段）
  1. 檢查持仓盈虧
  2. 移動止盈點（如果觸發 +15%）
  3. 監控是否觸發止損
  4. 記錄當週的執行情況

週末（總結階段）
  1. 彙總周報（進場、出場、盈虧）
  2. 分析信號質量
  3. 準備下週計劃
```

### 風險管理檢查清單

```
每筆進場前：
  ☐ 檢查現有持仓數量（不超過 6 個）
  ☐ 檢查可用資金（≥ 83,333 元）
  ☐ 驗證信號條件是否滿足
  ☐ 確認股票代碼和數量

每日監控：
  ☐ 檢查止損點是否觸發
  ☐ 檢查追蹤止盈點是否移動
  ☐ 檢查 4 週持仓是否到期
  ☐ 確認沒有交易錯誤

月度複審：
  ☐ 统計本月勝敗比
  ☐ 統計本月平均報酬
  ☐ 檢查信號質量變化
  ☐ 決定是否調整參數
```
