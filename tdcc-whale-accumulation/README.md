# TDCC 大戶吃貨現象實證研究

## 📋 專案概述

本研究旨在**驗證台灣股市的「大戶吃貨後飆股」現象是否真實存在**，以及該現象的統計特徵和可預測性。

### 研究問題
- **現象定義**：大戶持股集中度上升（吃貨），股價隨後是否會出現井噴式上漲（飆股）？
- **是否真實**：這是生存者偏差的錯覺，還是真實存在的市場規律？
- **量化指標**：成功率、等待時間、平均漲幅、標的差異等

---

## 🔬 研究方法

### 1. 數據來源
| 數據源 | 指標 | 時間範圍 | 說明 |
|-------|------|--------|------|
| **TDCC（集保中心）** | 400張以上流動持股占比 | 過去1年（API限制） | 大戶持股指標，反映機構/主力進出 |
| **Yahoo Finance / 台股** | 日K線（開收高低、成交量） | 同步 | 股價走勢與成交量 |

### 2. 關鍵定義

#### 📌 「吃貨」樣態識別（底部堆積）
```
條件：
✓ 股價相對低點：相比前後30天的平均價格有明顯下跌
✓ 成交量在：成交量異常放大（Z-score > 0.5）
✓ 盆地形態：呈現 V 型或 U 型底部，持續 3+ 天
✓ 時序確認：TDCC 持股占比同步上升
```

#### 📌 「飆股」現象確認（爆發性上漲）
```
條件：
✓ 時間點：吃貨結束後的交易日
✓ 漲幅：至少出現 2 根 5% 以上的紅 K（日漲幅 ≥ 5%）
✓ 連續性：價格沒有嚴重回檔（回檔幅度 < 總漲幅的 30%）
✓ 力度：平均日成交量隨之放大
```

### 3. 分析框架

#### Phase 1: 數據蒐集
- 爬蟲所有台股（約 1,600+ 檔）的 TDCC 數據
- 配對對應的日K線資料
- 建立時間序列資料庫

#### Phase 2: 樣態識別
- 利用統計方法（Z-score）識別「吃貨」樣態
- 追蹤吃貨後 N 個交易日的股價走勢
- 判斷是否出現「飆股」現象

#### Phase 3: 統計分析
- **成功率**：出現吃貨後出現飆股的比例
- **時間統計**：吃貨到飆股的平均等待時間分佈
- **收益統計**：成功個案的平均漲幅、最大回檔
- **標的分類**：不同行業/市值是否有差異

#### Phase 4: 因果推斷與驗證
- 控制變數（市場大盤、行業漲跌）
- 排除倖存者偏差
- 評估實務可行性（交易成本、滑點）

## 📊 預期輸出

1. **統計報告**
   - 吃貨→飆股成功率（%）
   - 平均等待天數
   - 平均漲幅（%）

2. **數據集**
   - `tdcc_data.csv` - 所有股票的 TDCC 持股數據

   - SQLite 數據庫 - 便於後續查詢

3. **可視化**
   - 成功率分佈圖
   - 等待時間分佈（直方圖）
   - 個案K線圖（吃貨區間 vs 飆股區間）

## 🚀 快速開始

### 1. 環境設置
```bash
cd /home/tom/stock-verify/tdcc-whale-accumulation
pip install -r requirements.txt
```

### 2. 爬取 TDCC 數據（樣本）
```bash
python src/crawler/main.py --stocks 0050,1101,2330 --output data/tdcc_data.csv
```

### 3. 執行分析
```bash
python src/analysis/statistics.py --input data/tdcc_data.csv
```

### 4. 運行測試
```bash
pytest tests/ -v
```

## ⚠️ 關鍵假設與限制

### 假設
- TDCC 持股數據準確代表大戶進出
- 日K線數據完整無缺口
- 過去一年的數據足以代表市場規律

### 限制
- **數據深度**：TDCC API 僅能回溯 1 年（無法做 5 年回測）
- **實時性**：爬蟲無法實時監控，需要每日定時執行
- **反爬蟲**：TDCC 網站可能有速率限制或 IP 阻擋
- **交易成本**：分析不包含手續費、稅金、滑點等
