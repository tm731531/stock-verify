### 疑慮點 ⚠️

1. **進場延遲風險嚴重**
   ```
   TDCC 週五公佈 → 信號識別 → 下週一掃描 → 下週一/二 進場

   • 訊號延遲 3-4 天（資訊不對稱）

4. **止損執行的實務風險**

   - 原因：低價股、停牌、跳空開盤
   - 實盤可能虧損更多

5. **最大回撤 -7% 的計算**
   - 聲稱最大回撤 -7%
   - 但未見逐日淨值曲線
   - 無法驗證是否正確

## 🎯 進出邏輯詳細評估

### 進場邏輯：是否合理？

#### 主引擎（3 週連升 + 同步比 + 散戶逃離）

**交易員的角度**：

✓ **可理解的邏輯**
```
3週連升 → 大戶持續買入
同步比≥50% → 1000張大戶跟進
散戶逃離≥2% → 確認散戶拋售
股價≥300元 → 過濾流動性差的股票

這反映了典型的「大戶佈局、散戶逃離」的市場結構
```

✗ **實務問題**
```
1. 為什麼散戶要在大戶已經介入後才逃離？
   → 通常是：大戶悄悄買 → 股價漲 → 散戶被套 → 才逃離
   → 這是落後指標，不是領先指標

2. 3週連升後，股價可能已經上升 20-30%
   → 進場成本高
   → v7 的驗證發現：平均買入延遲 -2.4%（買得更高）

3. 股價≥300元的限制太高
   → 排除了大量潛力股票
   → 主引擎只執行 67 筆（33% 的交易）
   → 備用引擎反而成為主力（67%）
```

**交易員評分**：6/10（邏輯可理解，但執行困難）

#### 備用引擎（15% 散戶逃離 + 大戶增加 2%）

**交易員的角度**：

✓ **更符合市場現實**
```
散戶大幅逃離（15%）→ 恐慌拋售
大戶增加（2%）→ 機構抄底
這是典型的「恐慌-介入」週期

這個邏輯比主引擎更符合實盤！
```

✗ **但數據顯示的矛盾**
```
備用引擊勝率 45.5% > 主引擊 38.8%
備用引擊利潤佔比 81.4% > 主引擁 18.6%

問題：為什麼更好的信號要排在「備用」位置？
       應該考慮提高備用引擊的優先級
```

**交易員評分**：8/10（邏輯更符合實盤，表現也更好）

### 出場邏輯：是否合理？

#### 止損 -7% ✓ **合理**

**交易員看法**：
```
-7% 的止損點很標準
• 足夠寬鬆，不會被震盪出局
• 足夠嚴格，控制單筆虧損
• 與台股的日均波動 2-3% 相符

但實務風險：
• 低價股（50-100 元）流動性差
  → 止損單可能無法成交
  → 可能虧損 -10% 以上
• 建議：低價股提高止損點到 -10%
```

#### 追蹤止盈 +15%觸發，-10% 出場 ✓ **合理**

**交易員看法**：
```
這個設定很聰明
• +15% 確認趨勢確立（不是反彈）
• -10% 跌幅足夠捕捉大部分利潤
• 避免過度貪心被反噬

實盤執行：
• 需要自動化系統，手工難以執行
• 追蹤止盈佔 15 筆（7.5%），比例偏低
• 可能是因為大多數股票在 42 天內未達 +15%
```

#### 期滿出場 42 天 ✓ **很好**

**交易員看法**（重點！）：
```
42天（6週）是短期趨勢的最優持倉期

為什麼？
1. TDCC 資料延遲 3-5 天
2. 大戶操作週期通常 4-8 週
3. 散戶心態改變需要 3-4 週
4. 超過 6 週，大戶可能已經走人

數據驗證：
• 期滿出場平均 +17.85% ← 最高！
• 186 筆交易中 86 筆期滿（42.8%）
• 這是總利潤的 1,277,337 元（71.4%）

相比 v7 的 90 天：
• 期滿回報只有 5%
• 被停損的交易多（15 筆 / 52 = 29%）
• 90 天太長，大戶已走，股價反轉

【結論】42 天 > 90 天，這是 v8 優秀的核心原因
```

**交易員評分**：9/10（優秀的持倉期設定）

## ⚠️ 實務可行性評估

### 關鍵問題 1：進場延遲

**現象**：
```
TDCC 週五公佈 → 隔週掃描 → 隔週一/二進場
進場延遲：5-7 天
```

**交易員的真實困境**：
```
實務問題：
1. 股價已變動
   例：3443 預期 742 → 實際 763（-21 = -2.8%）

2. 限價單未必成交
   例：如果股價已漲 5%，限價單會無法成交
   例：隔週才掛單，股票可能已漲 10%+

3. 低流動性股票無法進場
   例：低價股（50-100 元）掛單當日無法成交

4. TDCC 資料的有效期
   例：TDCC 週五發佈，下週一用資料進場
   → 實務上已經延遲 8 天以上
```

**改進方案**：
```
建議 1：改用「提前掛單」
  • 週四下午預先掃描，準備掛單
  • 週五 TDCC 公佈後，直接掛單
  • 減少延遲至 2-3 天

建議 2：分層進場
  • 第一層：週一開盤掛限價單（訊號日收盤 × 1.00）
  • 第二層：週二/三掛限價單（訊號日收盤 × 1.02）
  • 第三層：週四掛限價單（訊號日收盤 × 1.03）

建議 3：篩選股票流動性
  • 日均成交量 > 500 萬 (或自訂)
  • 避免低流動性股票無法進場
```

### 關鍵問題 2：主備順序的邏輯矛盾

**現象**：
```
回測報告：201 筆 = 主 67 + 備 134
意思：主備同進（同日混用）

修正版：81 筆 = 主 79 + 備 2
意思：有主沒備（排他性）

問題：哪個才對？
```

**交易員的建議**：
```
從績效看，「主備同進」更好：
  • 201 筆 vs 81 筆（樣本 2.5 倍）
  • 年化 52.9% vs 11.1%（性能大幅下降）

從邏輯看：
  • 備用引擁勝率更高（45.5% > 38.8%）
  • 備用引擁利潤更多（81.4%）
  • 為什麼要排斥更好的引擎？

實務建議：
  ✓ 採用「主備同進」邏輯（當前版本）
  ✓ 但考慮「提高備用優先級」

  可能的優化：
  1. 週內進場限制改為「主優先」
     → 先進主，滿倉後進備
  2. 或者「備用優先」（因為勝率更高）
```

**交易員評分**：5/10（邏輯不清，有重大分歧）

### 關鍵問題 3：風險控制是否足夠

**交易員檢查清單**：

```
✓ 止損設定：-7% （足夠）
✓ 持倉限制：6 倉 （足夠分散）
✓ 單倉金額：83,333 元 （可承受）
✓ 追蹤止盈：+15% 啟動 （聰明）
✓ 期滿出場：42 天 （很好）

✗ 缺少的風控：
  1. 連續虧損限制
     → 建議：連續 3 次止損 → 檢查信號
     → 建議：連續 5 次虧損 → 暫停進場

  2. 單週進場限制
     → 回測中「每週 2 筆」，但實際平均 5.8 筆？
     → 持倉滿 6 個後，應該等待？還是繼續進場？

  3. 月度風控
     → 建議：月虧損 > 5% → 暫停進場
     → 建議：月虧損 > 10% → 複審訊號品質

  4. 流動性監控
     → 低價股（<100元）止損難度高
     → 建議：根據股票流動性調整止損點

✗ 完全缺失：
  1. 滑點假設（實盤會滑點 1-3%）
  2. 系統風險（自動化系統故障）
  3. 假訊號風險（若市場環境改變）
```

## 📊 報酬計算是否正確？

### 總報酬 +173.04% 的核算

**交易員的檢查**：

1. **計算邏輯驗證**
   ```
   初始資本：500,000 元
   最終淨值：1,365,202 元
   利潤：865,202 元

   報酬率計算：
   865,202 / 500,000 = 1.7304 = 173.04% ✓

   年化計算：
   173.04% / 3.27 年 = 52.9% ✓

   邏輯無誤
   ```

2. **組成驗證**
   ```
   主引擊：+160,634 元（18.6%）
   備用引擊：+704,568 元（81.4%）
   總計：+865,202 元 ✓

   邏輯無誤
   ```

3. **出場方式驗證**
   ```
   期滿出場（86筆）：+1,277,337 元
   止損出場（96筆）：-593,845 元
   追蹤止盈（15筆）：+144,399 元
   數據截斷（4筆）：+37,311 元
   ──────────────────────
   合計：+865,202 元 ✓

   邏輯無誤

### 但實盤能否達成？

**交易員的實務評估**：

```
回測條件 vs 實盤差異：

1. 進場延遲
   - 回測：日內進場
   - 實盤：延遲 3-5 天 (甚至無法進場)
   - 影響：-2-5% 進場成本

   - 回測：精確 -7%

   - 回測：假設全部能成交
   - 實盤：部分股票無法進場或出場
   - 影響：完全無法進場 = 0 筆交易

4. 系統故障風險
   - 回測：無此風險
   - 實盤：自動化系統可能故障
   - 影響：漏單、誤單

【保守估計實盤績效】
  回測：52.9% 年化
  → 考慮進場延遲 -5% = 47.9%
  → 考慮止損滑點 -2% = 45.9%
  → 考慮流動性無法進場 -5% = 40.9%

  【實盤預期：40-45% 年化】
```

## 🎓 交易員的最終評估

### 優點 ✓

1. **出場邏輯優秀**
   - 期滿 42 天 = 最佳短期持倉期
   - 止損明確，追蹤止盈聰明
   - 多層出場機制完整

2. **風險分散**
   - 6 倉分散風險
   - 單倉虧損可控（-5,833 元）
   - 最大回撤相對小

3. **信號相對有邏輯**
   - 大戶連升有跡可循
   - 散戶逃離反映市場心態
   - 非完全隨機

4. **樣本充足**
   - 201 筆交易足以驗證
   - v7 的 52 筆太少

### 缺點 ✗

1. **進場延遲嚴重**
   - TDCC 週五 → 隔週掛單 = 延遲 5-7 天
   - 低流動性股票可能無法進場
   - 預期虧損 2-5% 只為進場

2. **邏輯有分歧**
   - 主備順序不清（同進 vs 排他）
   - 修正版性能崩潰，原版反而更好
   - 備用優於主，為何不提高優先級？

3. **實盤 vs 回測差距大**
   - 回測 52.9% → 實盤預期 40-45%
   - 主要原因：進場延遲、流動性、滑點

4. **風控不足**
   - 缺少連續虧損限制
   - 缺少每週進場邏輯
   - 缺少月度風控機制

### 交易員的推薦

```
結論：可行，但需要改進

適合：
  ✓ 有完整自動化系統的機構
  ✓ 資本充足（可承受延遲進場）
  ✓ 願意承受 40-45% 年化（vs 52.9% 回測）

不適合：
  ✗ 小資本（無法承受流動性風險）
  ✗ 手工下單（進場延遲會很大）
  ✗ 風控不嚴格的交易者

改進建議優先級：
  1️⃣ 解決進場延遲（改用提前掃描或分層進場）
  2️⃣ 澄清主備邏輯（同進 vs 排他，及優先級）
  3️⃣ 加強風控機制（連續虧損、月度限制、流動性篩選）
  4️⃣ 實盤驗證 3 個月（確認預期績效）

【最終評分】
  進出邏輯：7/10（邏輯清楚，但有矛盾）
  實務可行性：6/10（延遲、流動性是大問題）
  風險管理：6/10（基本完整，但不足）
  報酬預期：5/10（回測 52.9% 可能過於樂觀）

  【綜合評分：6/10】可行但需改進
```
