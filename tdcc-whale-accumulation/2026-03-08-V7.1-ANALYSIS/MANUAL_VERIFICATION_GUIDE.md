# TDCC 鯨魚策略 v7.1 - 人工驗證指南

**驗證目的**：確認所有 75 筆（90天+3個）或 103 筆（42天+3個）交易的真實性
**驗證方法**：逐筆交易核對數據庫和股票走勢圖
**預期時間**：每筆交易 3-5 分鐘，共需 4-8 小時（建議分批進行）

## 📋 人工驗證流程

### 步驟 1：準備驗證工具

需要訪問以下資源：
```
1. 台灣股市數據庫
   - 台灣證交所 (https://www.twse.com.tw/)
   - 或 Yahoo Finance (https://tw.finance.yahoo.com/)
   - 或其他股票資料軟體（如 Wantgoo、工商時報等）

2. TDCC 持倉數據
   - 台灣集中保管結算所 (https://www.tdcc.com.tw/)
   - 或 Goodinfo (https://www.goodinfo.tw/)
   - 可查詢 r400、r1000 等持倉數據

3. 詳細交易紀錄
   - 本項目提供的 CSV 檔案
   - /trade_details/trades_detail_*.csv
```

### 步驟 2：選擇驗證樣本

**方案 A：系統抽樣（推薦）**
```
樣本量：每個配置抽取 5-10 筆
抽樣方法：每 10 筆取 1 筆（系統抽樣）

示例（90天+3個，共 75 筆）：
- 第 10 筆、20 筆、30 筆、40 筆、50 筆、60 筆、70 筆
- 共 7 筆樣本（抽樣率 9.3%）
```

**方案 B：隨機抽樣**
```
樣本量：每個配置 5-10 筆
方法：亂數產生器隨機選擇行號
```

**方案 C：重點驗證**
```
- 最大獲利交易：1 筆
- 最大虧損交易：1 筆
- 中位數附近交易：2 筆
- 停損與到期各 1-2 筆
```

### 步驟 3：逐筆驗證項目

每筆交易需驗證以下 8 項：

#### 3.1 進場信息驗證

| 驗證項 | CSV 欄位 | 檢驗方法 | 預期結果 |
|--------|---------|--------|--------|
| **進場日期** | entry_date | 查股價圖，確認該日確實有交易 | ✓ 該日股價波動 |
| **進場股票代碼** | code | 確認股票代碼格式正確（4位數字） | ✓ 如 2330、3443 等 |
| **進場價格** | entry_price | 查股價圖，進場價應在該日 OHLC 內 | ✓ 進場價 ≤ 該日最高價 |
| **進場價合理性** | entry_price | 檢查進場價是否異常（太高/太低） | ✓ 進場價與前日收盤相近 |
| **信號類型** | type | 確認是 'main' 或 'backup' | ✓ main（主引擎）或 backup（備位） |

**具體驗證方式**：
```
例：交易 #1
CSV 記錄：6472, 2022/12/05, 464.0 (main)

驗證步驟：
1. 打開台灣股市 (代碼 6472)
2. 查看 2022/12/05 的股價
3. 確認該日股價確實經過 464 元
4. 檢查該日 OHLC：如果開盤 470, 最低 455, 最高 475, 收盤 460
   → 進場價 464 確實在該日交易範圍內 ✓
```

#### 3.2 出場信息驗證

| 驗證項 | CSV 欄位 | 檢驗方法 | 預期結果 |
|--------|---------|--------|--------|
| **出場日期** | exit_date | 查股價圖，確認該日股價 | ✓ 該日確有交易 |
| **出場價格** | exit_price | 出場價應在該日 OHLC 內 | ✓ 出場價 ≥ 該日最低價 |
| **出場理由** | reason | 檢查是 '停損' 或 '到期' | ✓ 根據虧損/天數判斷 |
| **持倉天數** | hold_days | 驗證出場日 - 進場日 = 持倉天數 | ✓ 日期差正確 |

**具體驗證方式**：
```
例：同上交易 #1
進場：2022/12/05 @ 464
出場：2022/12/06 @ 418

驗證步驟：
1. 查 2022/12/06 股價，確認該日最低價 ≤ 418 ✓
2. 計算損益：(418-464) / 464 = -9.9%
3. 驗證停損：-9.9% ≈ -10%（超過 -7%停損點） ✓
4. 驗證原因：理由應為 '停損' ✓
5. 驗證天數：2022/12/06 - 2022/12/05 = 1 天 ✓
```

#### 3.3 損益計算驗證

| 驗證項 | CSV 欄位 | 檢驗方法 | 公式 |
|--------|---------|--------|------|
| **損益金額** | pnl | 驗證計算 | (exit_price - entry_price) |
| **損益百分比** | pnl_pct | 驗證計算 | ((exit_price/entry_price) - 1) × 100% |

**具體驗證方式**：
```
例：交易 #16
進場：2023/05/05 @ 180 元
出場：2023/08/04 @ 402.5 元

驗證：
1. 損益金額 = 402.5 - 180 = 222.5 ✓
2. 損益百分比 = (402.5/180 - 1) × 100% = 123.6% ✓
3. 理由：到期（91 天 ≈ 90 天配置） ✓
```

#### 3.4 持倉天數驗證

**驗證方法**：
```
配置 90 天：
- hold_days 應在 88-92 天範圍（允許±2 天誤差）
- 原因應為 '到期'

配置 42 天：
- hold_days 應在 40-44 天範圍
- 原因應為 '到期'

配置停損出場：
- hold_days 可以任意（1-90 天）
- 但 pnl_pct 應接近 -7%（±0.5%）
```

**具體驗證方式**：
```
例：90天+3個 配置
進場：2023/05/05
出場：2023/08/04
hold_days = 91

驗證：
1. 日期差計算：(2023/08/04) - (2023/05/05) = 91 天 ✓
2. 在 90±2 天範圍內 ✓
3. 原因應為 '到期' ✓
```

#### 3.5 股票流動性驗證

對於高價股（進場價 ≥ 300 元），驗證：
```
檢查項：
□ 股票是否在台灣上市
□ 進場日股票是否有交易（非停牌）
□ 日均成交量是否 > 100 張（流動性充足）
□ 進場價是否在合理範圍（非極端價格）
```

### 步驟 4：統計驗證

驗證完成樣本後，進行統計檢驗：

#### 4.1 勝率驗證
```
計算方式：
獲利筆數 / 總筆數

期望結果（90天+3個）：
23 / 75 = 30.7%

樣本驗證：
如抽取 10 筆，期望獲利 3 筆（±1 筆誤差範圍）
```

#### 4.2 平均單筆驗證
```
計算方式：
總利潤 / 總筆數

期望結果（90天+3個）：
651,422 / 75 = 8,686 元

樣本驗證（10 筆樣本）：
平均單筆應在 7,000 - 10,000 元範圍
```

#### 4.3 停損有效性驗證
```
檢查項目：
□ 停損出場時，pnl_pct 是否在 -6% 到 -7.5% 範圍
□ 無異常大虧（如 -15% 以上仍未停損）
□ 停損觸發時機是否及時（無延遲）
```

## ⚠️ 可能遇到的問題

### 問題 1：進場價在 OHLC 外
**原因**：
- 時間對齊問題（使用周收盤而非日收盤）
- 股票停牌導致無法進場
- 進場延遲（信號日後進場規則）

**解決方法**：
- 確認進場是否在信號日後 3-7 日
- 檢查該期間股票是否停牌
- 確認使用日線還是周線數據

### 問題 2：損益計算不符
**原因**：
- 四捨五入誤差
- 股票分割或配息
- 手續費計算差異

**解決方法**：
- 允許 ±0.1% 的誤差範圍
- 驗證股票該期是否有分割/配息
- 確認手續費是否已扣除

### 問題 3：無法查到股票數據
**原因**：
- 股票已下市
- 使用了舊代碼
- 數據來源不同步

**解決方法**：
- 查詢股票代碼是否正確
- 確認股票上市期間是否涵蓋交易日
- 嘗試其他數據來源（Wantgoo、Yahoo Finance）
