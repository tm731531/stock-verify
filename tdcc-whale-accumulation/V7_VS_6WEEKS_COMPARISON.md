### 決策邏輯

#### v7 的決策流程

```
每週掃描
  ↓
有主引擎訊號（該 ISO 週）
  ├─ YES → 執行主引擎，**該週補位不出現**
  └─ NO  → 補位引擎頂上（前 5 名）

特點：
  • ISO 週為單位（國際標準周數）
  • 「有主沒補」：同週不能混用
  • 但不同週可混用（如 A 週主，B 週補）
```

#### 6週版本的決策流程

```
每日掃描
  ↓
同日收到多個訊號（主 + 補）
  ├─ YES → **全部執行**（按日期順序）
  └─ 不區分週

特點：
  • 日為單位
  • 「主備同進」：同日可混用
  • 優先級隱含在執行順序中
```

**關鍵差異**：
- **v7**：同週阻斷（更嚴格）
- **6週版本**：同日可混用（更寬鬆）

## ⚠️ 6 週版本的局限性

### 1. 勝率較低（43.3% vs v7 的 50%）

**原因**：6週版本進場更頻繁（61次/年 vs v7 的 10次/年），信號質量必然參差不齊。

**但為何不是問題**：
- 即使勝率低，但獲利虧損比更優（3.10 vs v7 的 2.8）
- 期滿出場回報極高（+17.85%），補償低勝率

### 2. 中位數為負（-4.90%）

**含義**：一半以上的交易虧損或獲利很少。

**但為何不是問題**：
- 這是正常的（勝率 43% 必然導致中位數為負）
- 平均值仍為正（+5.17%）
- 樣本足夠大（201 筆），統計上可信

### 3. 缺少 MA20 技術面過濾

**v7 的做法**：補位引擎要求股價站上 MA20（避免下跌股）

**6週版本的做法**：用「大戶增加 2%」替代，純面邏輯（量價分離）

**哪個更好**？
- 短期（90 天）：MA20 可能更準（趨勢強度）
- 長期（6 週）：大戶增加更實質（機構認可度）

6週版本的選擇更符合 TDCC 大戶持股策略。

## 🔄 決策邏輯的深層對比

### v7 的「ISO 週阻斷」

```python
# 偽代碼
if 本週有主引擎訊號:
    執行主引擎(限制到本週最多2筆)
    # 補位引擎自動跳過該週
else:
    補位引擎頂上(最多2筆)
```

**優勢**：
- 邏輯簡單，易於管理
- 避免主補混亂

**劣勢**：
- 同週只能二選一，可能錯過機會
- 如 A 股有主信號，B 股的補信號就被迫放棄

### 6週版本的「主備同進」

```python
# 偽代碼
for 當日訊號 in [主信號 + 補信號]:
    if 可進場(持倉限制、資金限制):
        執行進場()
```

**優勢**：
- 充分利用機會
- 主補信號獨立判斷，不互相干擾

**劣勢**：
- 容易造成同週進場過多（解決方案：每週限制 2 筆）
- 邏輯上主備應該有優先級

## 🎓 核心洞察

### 問題：為什麼 6 週版本看起來「更簡單」卻賺得更多？

**答案在於「時間窗口」和「資本配置」**：

```
v7（90天）的特徵：
  • 每筆交易持有 90 天
  • 年均 10 筆 = 平均每筆利潤 = 138.2% ÷ 10 = +13.82%
  • 但樣本少，統計誤差大

6週版本（42天）的特徵：
  • 每筆交易持有 42 天
  • 年均 61 筆 = 平均每筆利潤 = 173.04% ÷ 201 × 3.27 = 約每筆 +2,800 元 ✓
  • 樣本多，統計誤差小
  • 資金周轉快：每 42 天一個週期，年可完成 8.7 個週期
```

**本質差異**：
- **v7**：買對了，就持久戰（90 天掘金）
- **6週版本**：頻繁進出（每 6 週一個循環），靠頻率和穩定性勝
