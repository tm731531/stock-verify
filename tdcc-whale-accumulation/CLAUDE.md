## 核心系統規格

### 進出場邏輯 (v7 已驗證)

#### 主引擎 (Signal-driven)
- **進場時間窗口**: 信號日後 +3 至 +7 天（最多等 5 天）
- **進場條件**: 只要 `close_price ≤ limit_price`（信號日收盤 × 1.03）
- **進場價格**: 隔天以 `close_price` 掛單進場（使用實際成交價，不用 limit_price）
- **周限制**: ISO 週最多 2 筆進場（防過度集中）

#### 備位引擎 (CRONTAB v7)
- **進場條件** (同時滿足):
  - 4 週散戶減少 ≥5.0%（相對於 4 週前）
  - 股價 > MA20
  - 股價 ≥50 元
- **進場日期**: 信號日期 +5 個交易日（如果未被主引擎覆蓋）
- **去重邏輯**: 同一週內若主引擎已有信號，備位自動跳過（防重複掛單）

#### 出場邏輯 (通用)
1. **停損**: -7% 直接出場
2. **獲利**: +15% 啟動，回檔 10% 執行
   - 當 `pnl_pct >= 15.0` 時，設 `take_profit_activated = True`
   - 記錄 `highest_pnl_since_activation`
   - 若 `highest_pnl - current_pnl >= 10.0` 則執行出場
3. **到期**: 達到日曆天數限制（不是交易日計數）
   - 6 週配置: 42 日曆日
   - 90 天配置: 90 日曆日
   - **實現方式**: 每個日曆日檢查（包括週末假日），即使沒有當日價格，也會在次日有價格時執行已過期的出場

#### 日曆日計算 (CRITICAL)
```python
# 正確實現
from datetime import datetime, timedelta

entry_date_obj = datetime.strptime(entry_date, '%Y%m%d')
current_date_obj = datetime.strptime(current_date, '%Y%m%d')
calendar_days = (current_date_obj - entry_date_obj).days

# 出場條件
if calendar_days >= max_hold_calendar_days:  # 使用 >=，不是 >
    should_exit = True
    reason = '到期'
```

**重要**:
- 日曆日 = 純粹日期差異，包括週末和假日
- 不是交易日計數
- 需要迴圈所有日曆日（`while current_date <= end_date`），不只有交易日
- 假日市場休市時，位置可能超期等待有價格的次日出場（可接受）

## Crontab 自動掃描

### 排程設定
- **執行日期**: 週日早晨 09:00 (GMT+8)
- **執行腳本**: `v7/scan_notify.py`
- **功能**: 掃描上週最後一個交易日的 TDCC 新信號

### TDCC 資料發佈時間表
- **發佈頻率**: 一週一次，在每週最後一個交易日
- **上週** (2026-02-28～2026-03-06): 週四 2026-03-06 發佈
- **本週** (2026-03-07～2026-03-14): 週五 2026-03-14 發佈
- **掃描時機**: 每週週日 09:00 掃描上週五（或週四）發佈的資料

### 訊號與通知
- 掃描結果通過 LINE Notify 推送到手機
- 去重機制: 相同訊號日期若已通知過，自動跳過（防重複通知）
- 分析時間: 掃描 → 分析 → 通知，約 1-2 分鐘

## 已知限制與注意事項

### 假日市場休市
- 中國新年期間（通常 1-2 週）市場全閉
- 位置可能延遲到次個有交易日才能出場
- 此時延期 7-14 天持倒 **可接受**（無法控制市場休市）

### 進場資金
- 每個配置只計算 4 或 6 個持倉位的資金需求
- 範例: 4 位 × 125K = 500K 本金起跳
- 實際資金應預留 20% 安全墊（應急需求）

### 日期範圍
- 回測範圍: 2022-01-01 ～ 2025-12-31（完整 4 年）
- 隔離 2023 年空頭測試（確認在不同市況的表現）
- 生產運行: 2026 年至今
