# TDCC 鯨魚策略：特殊事件排除永久 vs 一年機制回測對比

## 重點摘要

- 特殊事件排除機制對策略績效有顯著影響
- **永久排除勝過一年制**：報酬高 15.32%（50.37% vs 35.05%）
- 永久排除版本勝率更高（50% vs 40.4%）、虧損更少
- 曾有特殊事件的股票（單週 >5% 變動）通常存在結構性缺陷

---

## 前言：何謂特殊事件排除

在 TDCC 大戶吃貨策略中，**特殊事件** 指的是單週 `ratio_400_above` 變動超過 5% 的情況。這類事件通常代表：

- **併購、下市、減資** — 財務重組導致持股結構劇變
- **股權變動** — 大股東增減持
- **異常成交量** — 特定事件觸發的非理性交易

**問題**：這些股票往往具有「結構性缺陷」，即使後續恢復，也容易再次出現類似異常。因此需要排除它們。

**但問題是**：要永久排除，還是只排除一年？

## 詳細分析

### 為何永久排除勝出

#### 1. **勝率優勢**（50% vs 40.4%）

永久排除版本的勝率高 9.6 個百分點。這表示：

- 被排除的股票（曾有特殊事件）訊號品質更低
- 即使進場，虧損機率也更高
- 1年排除放過這些「低品質訊號」，反而增加風險

#### 2. **虧損控制**（-150k vs -391k）

1年排除版本虧損多了 **240k**（+160%）。分析：

- 特殊事件股通常具有「二度特殊」的傾向
- 一旦恢復，可能再次發生類似事件
- 放過排除期後，這些股票仍容易在後續年份出現問題

#### 3. **平均交易規模**

- 永久排除：平均每筆獲利 11,457 元 (320k ÷ 28)
- 1年排除：平均每筆獲利 8,864 元 (460k ÷ 52)

**永giusdiquer年排除訊號品質更好**（每筆獲利更高），即使交易數少。

## 案例研究：為什麼特殊事件股是「問題股」

特殊事件通常對應以下情況：

### 案例 A：財務困境股
```
時間線：
  Q1 2024    ratio_400_above 10% → 15%（特殊事件發生）
  Q2-Q3 2024 恢復正常 12%
  Q4 2024    再度異常 11% → 18%（二度特殊）
  2025 後    進入悶盤或衰退

結論：不是「吃貨吸籌」，而是「特殊情況驅動」
      1年後排除解除 → 進場虧損
```

### 案例 B：流動性問題股
```
時間線：
  事件週    單週變動 >5% 因為交易量極小
  後續      散戶、法人都避開，成交量持續低迷
  1年後     仍然流動性差
  進場後    買/賣價差大，滑價嚴重

結論：除了特殊事件週外，根本問題未解決
      1年後排除解除 → 難以成交，虧損加重
```

## 建議與結論

### 實戰建議

✅ **採用永久排除機制**，理由：

1. **報酬更高**：50.37% vs 35.05%，高出 15.32 個百分點
2. **風險更低**：虧損控制優秀（-150k vs -391k）
3. **勝率穩定**：50% vs 40.4%，更容易預測交易結果
4. **品質篩選**：排除「結構性有問題」的股票

❌ **不建議用一年制**，理由：

1. 訊號數雖多（106 vs 47），但「品質差」
2. 虧損幅度大幅增加（240k 額外虧損）
3. 平均交易利潤更低（每筆 8,864 vs 11,457）

### 後續研究方向

1. **時變特性**：不同市場環境下，排除機制的效果是否改變？
2. **特殊事件等級**：單週 >5% 是否最佳閾值？試試 >7% 或 >10%？
3. **行業偏見**：是否某些產業的特殊事件股更容易再發？
4. **補位引擎影響**：補位引擎（散戶出逃 ≥5%）是否也需要相同排除邏輯？

## 技術細節

### 回測代碼架構

```python
# 兩種排除邏輯實現

def build_special_flags_permanent(tdcc_data):
    """永久排除：歷史上曾有單週 >5% 變動"""
    special = set()
    for code, grp in tdcc_data.items():
        for i in range(1, len(grp)):
            if abs(grp[i]['r400'] - grp[i-1]['r400']) > 5.0:
                special.add(code)
                break
    return special

def build_special_flags_expiry(tdcc_data, event_date, expiry_days=365):
    """1年排除：特殊事件排除標記 1 年後自動解除"""
    special = {}  # {code: event_date}
    for code, grp in tdcc_data.items():
        for i in range(1, len(grp)):
            if abs(grp[i]['r400'] - grp[i-1]['r400']) > 5.0:
                event_tdcc_date = grp[i]['date']
                event_dt = datetime.strptime(event_tdcc_date, '%Y%m%d')
                scan_dt = datetime.strptime(event_date, '%Y%m%d')
                days_diff = (scan_dt - event_dt).days
                if 0 <= days_diff <= expiry_days:
                    special[code] = event_tdcc_date
                break
    return special
```

## 結語

**特殊事件排除機制** 看似簡單，卻對策略績效有深遠影響。這次回測明確顯示：

> **永久排除不是「過度篩選」，而是「有效的風險管理」。**

被排除的 744 檔股票並非無辜的「誤傷」，而是真正存在結構性問題的「問題股」。一年後自動解除排除，反而讓這些問題股再次進入交易池，增加虧損。

此發現也為其他量化策略提供啟示：**並非所有歷史數據都值得利用，有時「聰明地忽略」，比「盡力利用」更能提升績效。**

## FAQ

**Q1：為什麼 1年排除訊號數多這麼多（+126%）？**

A：1年排除只臨時排除特殊事件股。隨著時間推移，1年期滿，這些股票重新進入掃描範圍。永久排除則一直排除，導致訊號數少很多。但重點是：多出來的訊號品質很差（虧損更多）。

**Q2：特殊事件的 5% 閾值是怎麼決定的？**

A：這是 v7 策略的既定參數。可以後續調整為 7% 或 10% 來測試是否有更好的效果，但本次回測固定用 5%。

**Q3：為什麼不用「特殊事件股比例」來加權調整？**

A：可以，但會增加策略複雜度。目前二分法（排除 vs 不排除）更簡潔，且績效已優異。後續可研究加權版本。

**Q4：永久排除是否會漏掉「真正改革的公司」？**

A：可能會。但從績效來看，這種風險遠小於「放過問題股再度出現異常」的風險。如果想獲取這部分收益，可嘗試 2年或 3年制（而非 1年制）。

**Q5：這套邏輯是否適用於補位引擎？**

A：補位引擎條件（散戶出逃 ≥5%）不同，需要獨立回測。但邏輯上「結構性有問題的股票應被排除」同樣適用。
