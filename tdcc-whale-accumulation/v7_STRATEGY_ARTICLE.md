# TDCC 鯨魚策略 v7.1：雙引擎量化交易回測與實戰指南

## 重點摘要

- **報酬 +114.3%**，Calmar 比率 **10.41**（超優異）
- 最大回撤僅 -11.0%（控制優異）
- 雙引擎設計：主引擎（大戶連升）+ 補位引擎（散戶出逃）
- v7.1 相比 v7.0：Calmar 提升 42%（7.31 → 10.41）
- 三項防禦性改進全數失敗，v7.1 已是最佳配置

---

## v7.1 策略全景

### 設計理念

TDCC 鯨魚策略採用 **雙引擎架構**：

1. **主引擎** — 捕捉「大戶主動吃貨」訊號（高勝率）
2. **補位引擎** — 撿「散戶恐慌賣出」的機會（高報酬但頻率低）

兩個引擎各司其職，避免訊號干擾。結果：報酬 114%，風險控制在 11%。

## 主引擎：大戶連升策略

### 進場條件（需全部滿足）

```
✓ 大戶持有比例連升 ≥ 3 週
  └─ ratio_400_above 連續上升（上一週 < 前一週 < 本週）

✓ 週增幅 ≥ 3%
  └─ ratio_400_above 累計變化 ≥ 3%

✓ 同步性 ≥ 50%
  └─ ratio_1000_above 變化 / ratio_400_above 變化
  └─ 表示大小戶同向程度

✓ 散戶持有人數在減少
  └─ total_holders 較起漲點下跌 ≥ 2%
  └─ 散戶在集中出逃

✓ 股價 ≥ 300 元
  └─ 高股價通常代表基本面穩健
  └─ v6d 數據證實：300+ 股票勝率 65%，500+ 股票勝率 80%

✓ 非 ETF、非特殊事件股
  └─ 排除 00 開頭股票
  └─ 排除歷史上有單週 >5% 變動的股票
```

### 訊號解讀

一個合格的主引擎訊號代表：

> **大戶在連續吃貨 → 散戶在恐慌賣出 → 股價穩健**

這是「吃貨成功」的典型特徵。

## 補位引擎：散戶出逃策略

### 進場條件

```
✓ 4 週持有人減少 ≥ 5%
  └─ total_holders[本週] vs total_holders[4週前]
  └─ 散戶大幅出逃訊號

✓ 股價站上 MA20
  └─ 用 TDCC 日期前 20 筆日線計算
  └─ 表示反彈力道已出現

✓ 股價 ≥ 50 元
  └─ 最低流動性要求

✓ 主引擎「靜默」的 ISO 週
  └─ 該週無主引擎訊號才啟動補位
  └─ 防止同週重複訊號
```

### 為何補位在「主引擎靜默」時才啟動？

**v7.0 的問題**：以月為單位（YYYYMM）判斷，導致：
- 同一個月內，主引擎和補位都可能啟動
- 訊號重疊，難以判斷哪個引擎起作用

**v7.1 的改進**：改為 ISO 週判斷
- 若該 ISO 週有主引擎訊號 → 不啟動補位
- 若該 ISO 週沒主引擎訊號 → 補位才動作
- 結果：補位訊號從 2 筆增加到 14 筆，Calmar 提升 42%

## 出場規則：三層停損/停利機制

### 1. 停損（硬止損）

```
觸發條件：虧損 ≤ -7%

邏輯：
  損失超過 7% 就立刻出場
  不等待反彈，紀律優先

保護作用：
  限制單筆虧損上限
  確保本金安全
```

### 2. 追蹤停利（軟止利）

```
啟動條件：漲幅達 +15%
  └─ 只有賺 15% 以上才啟動

觸發條件：從最高價回落 10%
  └─ 例如：最高點 320 元 → 回落到 288 元就出場
  └─ 避免獲利大幅縮水

優點：
  捕捉大漲（15% 以上）
  同時避免貪心（不會一直抱到跌停）
```

### 3. 到期（時間止損）

```
持有滿 90 天自動出場
  └─ 防止資金長期卡死
  └─ 強制 roll 到新訊號
```

### 三層機制的組合效果

```
實例 1：小漲就急跌
  +8% → -2% → 觸發停損 -7%
  結果：虧 7% 出場（成功）

實例 2：漲幅足夠但貪心
  +20% → +18% → 不跌 10% 就一直抱
  結果：可能又跌回 0%，虧損

實例 3：追蹤停利的效果
  +20% 啟動 → 漲到 +25% → 回落 10%
  結果：出場時約 +15% 左右（成功鎖利）

實例 4：躺著賺但不動
  +5% 但 90 天滿了
  結果：出場並 re-deploy 到新訊號（資金流動）
```

## v7.0 → v7.1 改進詳解

### 改進 1：r400 門檻提升（2% → 3%）

```
為什麼提升？
  ├─ 2% 門檻太低，容易抓到「假連升」
  │  └─ 只是震盪，不是真正的吃貨
  │
  └─ 3% 門檻更嚴格，只抓「確實的大戶動作」

結果：
  主引擎訊號減少（46 → 35）
  但勝率提升、虧損減少
  → 品質 > 數量
```

### 改進 2：補位封鎖單位改變（月 → ISO 週）

```
v7.0 邏輯：以月份（YYYYMM）判斷
  2024/01
  ├─ 2024/01/08 主引擎訊號 ✓
  │
  └─ 2024/01/22 補位訊號 × 同月被封鎖！
                   └─ 補位無法啟動

問題：
  └─ 同月可能有多個 ISO 週
     └─ 一個月封掉所有補位機會
     └─ 補位引擎幾乎無用

v7.1 邏輯：以 ISO 週判斷
  2024/W03（1/15-1/21）主引擎訊號
  └─ 該週的補位被封鎖

  2024/W04（1/22-1/28）補位訊號 ✓
  └─ 該週無主引擎訊號，補位啟動！

結果：
  補位訊號：2 → 14（+7 倍！）
  Calmar：7.31 → 10.41（+42%）
  → 補位引擎被激活
```

### 改進 3：backtest 呼叫邏輯修正

```
v7.0：
  backtest(all_signals, all_backup_signals)
  └─ 把全量補位傳進去，引擎自己過濾
  └─ 邏輯混亂、易出錯

v7.1：
  backup_signals = [s for s in all_backup_signals
                    if iso_week(s) != iso_week(main_signal)]
  backtest(main_signals, backup_signals)
  └─ 提前過濾，傳入已清潔的補位訊號
  └─ 邏輯清晰、結果正確
```

## 防禦性改進測試：全數失敗案例

v7.1 發佈前，團隊測試了三項防禦性改進。結論：**全部讓績效下降**，所以維持 v7.1 原始配置。

### 測試 1：冷卻期 90 天

```
假說：
  └─ 股票出場後 90 天內不再進場
  └─ 避免「重複買進已失敗股票」

結果：
  Calmar：10.41 → 9.34（-8.8%）

原因：
  ├─ 某些股票出場後確實反彈
  │  └─ 冷卻期讓我們錯過二次機會
  │
  └─ 「冷卻期」是小事，大戶邏輯才是核心
     └─ 如果訊號有效，何必冷卻期？

結論：
  ❌ 冷卻期擋壞也擋好，淨效果為負
```

### 測試 2：補位縮半倉

```
假說：
  └─ 補位訊號品質低，所以只進半倉（62,500 元）
  └─ 降低補位風險

結果：
  Calmar：10.41 → 5.40（-48%！）

原因：
  ├─ 補位半倉 → 獲利時賺一半
  │  └─ 14 筆補位訊號中，多筆為大獲利者
  │  └─ 砍掉獲利機會
  │
  └─ 虧損時仍虧 50%（停損不變）
     └─ 不對稱的風險縮減

結論：
  ❌ 補位訊號的 upside 很高，不應縮倉
```

### 測試 3：大盤濾網 MA60

```
假說：
  └─ 只在大盤站上 MA60 時進場
  └─ 避免空頭時的虧損

結果：
  Calmar：10.41 → 8.22（-21%）

原因：
  ├─ 歷史上大盤幾乎都站 MA60
  │  └─ 真正下跌的時間很短
  │  └─ MA60 濾網幾乎無效
  │
  └─ 反而卡掉某些小空頭時的機會
     └─ 小虧變沒進場（虛假繁榮）

結論：
  ❌ 大盤幾乎都站 MA60，濾網作用有限
```

### 小結：為什麼所有防禦性改進都失敗

```
核心原因：
  └─ TDCC 鯨魚策略本身已包含風險控制
     ├─ 大戶連升 = 低風險訊號
     ├─ 散戶出逃 + MA20 = 反彈訊號（不在全股灾）
     ├─ 停損 -7% 限制單筆虧損
     └─ 最長 90 天強制出場（不卡死）

添加額外防禦反而：
  ├─ 削弱高獲利機會（縮半倉）
  ├─ 過度濾網導致遺漏訊號（冷卻期、MA60）
  └─ 淨效果為負

結論：
  ✓ v7.1 當前配置已是最佳解
  ✓ 不要過度優化，簡單就是美
```

### 流程

```
週日早上 09:00
  │
  ├─ scan_notify.py 自動掃描
  │  └─ 取得本週訊號
  │
  ├─ LINE 推播（如已設定）
  │  └─ 代碼、買入價、限價、停損
  │
  ├─ 交易員檢視
  │  ├─ 掃描結果邏輯 OK？
  │  ├─ 個股基本面確認？
  │  └─ 資金部位 OK？
  │
  └─ 手動/自動下單
     └─ 限價單（訊號日後第 3-7 天）
```

### 進場技巧

```
訊號公布日（TDCC 日期）：不進場
  └─ 等待數據穩定

訊號日後第 3 天起：開始觀察
  └─ 收盤價 ≤ 限價就掛單
  └─ 限價 = 訊號日收盤 × 1.03（+3%）

訊號日後第 5-7 天內：停止掛單
  └─ 如果都沒成交，就放棄這個訊號

為什麼有 3-7 天窗口？
  └─ 給市場反應時間
  └─ 大戶也在買，不會馬上拉漲
  └─ 散戶恐慌，需要 3-5 天才會有跟風買盤
```

### 出場紀律

```
買入後每天監控：

狀況 1：虧損 ≤ -7%
  └─ 立刻止損，不要等
  └─ 紀律優先

狀況 2：獲利 +15% 且回落 10%
  └─ 執行追蹤停利
  └─ 例：買 100 → 漲到 115 → 回到 103.5 就賣

狀況 3：獲利 +5% ~ +14%
  └─ 繼續持有
  └─ 等候漲幅達 15% 啟動追蹤停利

狀況 4：買入滿 90 天
  └─ 強制出場（無論損益）
  └─ 釋放資金 deploy 新訊號
```

## 常見問題

### Q1：為什麼要設 300 元股價下限？

A：根據 v6d 研究（另一篇文章），股價越高訊號越準：
- 100-300 元：勝率約 30-40%
- 300-500 元：勝率約 65%
- 500+ 元：勝率約 80%

所以設 300 元是性價比最優點。

### Q2：為什麼同步性要 ≥50%？

A：表示大小戶變化的一致性。
- sync < 50%：大戶在吃，小戶在賣 → 訊號不清
- sync ≥ 50%：大小戶都在吃 → 確實是吃貨

這是「一致性」的檢驗。

### Q3：補位引擎為什麼只在主引擎靜默時啟動？

A：兩個引擎的訊號類型不同：
- 主引擎：大戶主動建倉（高確定性）
- 補位引擎：散戶恐慌賣出（機會型）

同週內不應混合，會造成倉位重複 deploy。

### Q4：為什麼要限制 4 檔持倉？

A：
- 太少（1-2 檔）：訊號浪費
- 太多（6+ 檔）：難以跟蹤、資金分散過度
- 4 檔最優：足夠多元，又能密切監控

### Q5：停損 -7% 太寬鬆嗎？

A：不會。根據回測，v7.1 只有 33% 的交易虧損，且平均虧損 -6.2%（早於停損）。市場會自己出場，停損 -7% 是最後的安全閥。

### Q6：為什麼追蹤停利要 +15% 才啟動？

A：
- +15% 以下的小漲可能反覆：不想頻繁出場
- +15% 以上是「確實的大漲」：這時啟動保護
- 回落 10% 的距離設定：既能鎖利，又不會太貪心

### Q7：Calmar 10.41 意味著什麼？

A：年化報酬 / 最大回撤比率極優，表示：
- 每承受 1% 回撤，就能賺 10.4% 年報酬
- 風險調整後的超額報酬很高
- 同級別策略的 Calmar 通常在 1-2 範圍，10+ 是天花板

## 結語

v7.1 雙引擎策略經過 9 年回測、三項防禦性測試、多次參數調優，已達成熟狀態。

**核心優勢**：
- 主引擎抓「確實的吃貨」（高勝率，66.7%）
- 補位引擎撿「散戶恐慌」（高報酬，平均 18.5%）
- 風險控制嚴格（停損 -7%、追蹤停利、90 天強制出場）
- 最大回撤只有 -11%，Calmar 10.41 超優異

**不建議再優化**：
- 冷卻期、縮半倉、大盤濾網全數失敗
- v7.1 當前配置已是最佳解
- 簡單的策略往往更robust

**下一步**：
- 實盤驗證（紙上談兵 vs 真實行動）
- 監控大環境變化（新制度、市場結構改變）
- 定期檢視（每季或每年），但不要過度優化
