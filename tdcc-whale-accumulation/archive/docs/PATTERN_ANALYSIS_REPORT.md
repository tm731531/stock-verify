### 1. **持倉時間決定勝負** ⭐⭐⭐

```

─────────────────────────────────────────
停損 (-7%)    423筆    0.0%    -12.1%   -NT$5,125K
到期 (42/90日) 366筆   77.3%   +16.5%   +NT$6,030K
```

**結論**：
- 到期出場 (設定天數) 的勝率是停損出場的 **∞倍** (77.3% vs 0%)
- 停損設定過緊 (-7%) 導致切肉
- 應該改為「到期即出」的策略，不依賴停損

## 🎯 信號篩選實戰建議

### 問題
每週 40+ 個備位引擎信號，但根據容量只能進場 2-3 個。
需要篩選條件將信號從 40+ 縮減到 2-3。

### 解決方案

#### **第一層篩選：價格** (必須)
```python
✅ 保留: 200 <= price <= 500  # 勝率 45-52%
❌ 排除: price < 100 或 price > 500  # 勝率 <30%
```
**預期效果**: 將 40 個信號減少到 ~15-20 個

#### **第二層篩選：散戶逃離幅度** (推薦)
基於 backup_v4 訊號的「逃離百分比」(fled_pct)：
```python
✅ 優先: -15% < fled_pct < -5%  # 適度逃離，確定性高
⚠️  警慎: fled_pct < -20%        # 過度逃離，可能恐慌
```
**預期效果**: 進一步縮減到 ~10 個信號

#### **第三層篩選：技術面** (推薦)
```python
✅ 優先: close_price > MA20  # 已反彈，未來跌幅有限
❌ 排除: close_price < MA20  # 仍在下跌，風險大
```
**預期效果**: 縮減到 ~5-8 個信號

#### **第四層篩選：週期** (可選)
```python
✅ 優先進場: 信號日期後 3-5 天內
❌ 延遲進場: 超過 7 天（機會已過）
```
**預期效果**: 最終確認 2-3 個最高品質信號

## ⚙️ 改進後的進場邏輯

基於分析結果，建議調整：

### 舊邏輯問題
1. 停損太緊 (-7%) → 導致在底部被切肉
2. 進場太急 (信號日+5天) → 沒有等到充分反彈確認
3. 持倉太短 (42/90天) → 無法讓獲利充分實現

### 新邏輯建議
```python
# 1. 進場條件
- 備位 v4 訊號（4週持續下降）
- 200 <= price <= 500  # 最佳價格區間
- close_price > MA20   # 已反彈
- -15% < fled_pct < -5%  # 適度逃離

# 2. 進場時機
- 信號日期後 +3~7 天（等待反彈確認）
- 條件: close_price <= limit_price (signal_date × 1.05)

# 3. 出場邏輯 (改進)
- 取消 -7% 停損
- 改為「到期出場」: 42日或90日
- 只在異常跌幅 (>-15%) 時才考慮止損

# 4. 位置管理
- 每週最多 2-3 個進場（根據品質篩選）
- 多頭市場: 90天+3個配置
- 空頭市場: 42天+6個配置
```
